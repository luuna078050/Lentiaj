# Ленивец — логика рекомендаций MVP

## 1. Учитывать не только холодильник
Инвентарь делится минимум на два контекста:
- **Холодильник/морозилка:** скоропортящиеся продукты, готовая еда, открытые упаковки.
- **Кладовая:** мука, крупы, макароны, сахар, специи, консервы, нори и другие продукты длительного хранения.

При анализе блюда движок объединяет оба контекста.

## 2. Принцип «самое простое решение сначала»
Приоритет выдачи:
1. 100% — можно приготовить/собрать прямо сейчас из имеющегося.
2. Минимальное действие — без готовки или с одним простым действием.
3. Если не хватает ингредиента — сначала предложить замену из имеющегося.
4. Если разумной замены нет — предложить докупить и, при разрешённой геолокации, показать варианты рядом.
5. Затем — «если хочешь чуть-чуть заморочиться»: более сложные блюда, если они соответствуют сырью, технике и времени пользователя.

## 3. Примеры
- Яйца + сосиски → яичница с сосисками = 100%.
- Макароны + сыр + масло → простая паста = 100%.
- Рис + нори + доступный белок/овощи → быстрый вариант в стиле суши/ролла с обязательной проверкой безопасности ингредиентов.
- Крупа + несколько круп в кладовой → предложить смесь круп и подходящий способ приготовления.
- Размороженная лопатка/шейка → сначала простые варианты, затем более сложные рецепты как необязательное предложение.

## 4. Safety-first
Для скоропортящихся продуктов учитывать срок, условия хранения, вскрытие, состояние упаковки и историю продукта. Подозрительные продукты не предлагать к употреблению. Внешний вид/запах не являются гарантией безопасности.

## 5. Персонализация
Учитывать диету, аллергии, непереносимости, предпочтения пользователя, доступную технику и привычный уровень сложности.
